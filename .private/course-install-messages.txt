# The Windows sign-off, which is the same moment reached down a different road (#218).
#
# WHY THERE ARE TWO. install-cs193v-windows.cmd runs the installer inside the CS193V WSL
# instance it has just made, so a Windows student reaches say_done exactly as a Mac one
# does -- but `cd` and `./cs193v` are not enough to get back here tomorrow. They need
# `wsl -d CS193V` first, and that step exists on no other platform. The .cmd used to print
# it afterwards in a block of its own, which meant a Windows install ended with two
# closing messages that disagreed; CS193V_WINDOWS is what turned them into one.
#
# {{UNC}} IS PASSED IN RATHER THAN WRITTEN HERE, and that is the defect this entry fixes
# as much as the missing wsl step. The .cmd's version of this path was the constant
# \\wsl.localhost\CS193V\home\student\cs193v\projects -- but choose_dir's menu runs on the
# Windows path too, so a student who chose any other directory was handed a path that did
# not exist. Only course-install.sh knows {{DIR}}, and win_projects_path builds it there.
# ─── the two arms that can promise a gesture  (#134) ───────────────────────────
#
# THE ONE-CLICK WAY LEADS AND THE TYPED COMMANDS STAY. Leading with the gesture is the whole
# point of #134 -- a student who has never used a terminal has something to do that does not
# involve one. Keeping the commands underneath is not hedging: it is the only thing that still
# works when the course folder has been moved, it is what staff will ask for over email, and on
# Windows it is already on screen if the .cmd's Start Menu step fails after this printed.
#
# {{LABEL}} RATHER THAN THE NAME SPELLED OUT, because that string is also the .app bundle's
# filename and the .lnk's, and 25-installer.sh asserts all three agree. Spelling it here would be
# a fourth copy, and the one nobody would think to check.
#
# THE FOUR ARMS MUST DIVERGE BEFORE THEIR FIRST {{PLACEHOLDER}}, and that is a constraint on the
# PROSE imposed by how this suite asserts. msg_text stops at the first placeholder, so two arms
# whose opening lines agree up to that point have the SAME needle and no keyed assertion can tell
# them apart -- including the ones that check a Windows sign-off did not leak into a UNIX run.
# Worse, containment is enough: an arm whose needle is a PREFIX of another's matches it too.
#
# These two both used to open "To start the development environment, open" and were therefore
# indistinguishable, which is what install:no-start-menu-step-without-the-flag found. They now
# diverge at "your Applications folder" against "your Start menu", and all four are pairwise
# non-containing -- which signoff-arms:are-mutually-distinguishable is what keeps true.

#  WHAT THE ROOT PASS PRINTS  (#217)
#
#  wsl-provision.sh reads this same catalogue. It runs once, as root, inside a CS193V
#  WSL instance that install-cs193v-windows.cmd created a minute earlier, and it
#  prepares that instance so the student's own install needs no password. A student
#  sees its `prov.*` lines go past between two things the Windows installer printed,
#  and normally reads none of them; they are here because the day one of them fails
#  is the day somebody has to understand what it was doing.
#
#  ONE CATALOGUE, TWO SCRIPTS, deliberately. A key may not live in two catalogues
#  (10-static.sh), so a second file would have meant a second copy of every shared
#  refusal -- and the two scripts are two halves of one installer as far as anyone
#  reading this is concerned.
# ═══════════════════════════════════════════════════════════════════════════════

# THE FOREIGN-ACCOUNT REFUSAL, WHICH IS THE ONE A REAL PERSON CAN REACH. It means
# the CS193V environment already has somebody's account in it -- almost always a
# CS193V set up by an earlier version of this installer, which asked the student
# to choose their own username. Creating a second account there would change
# which one they land in and where their files live, silently, so setup stops.
#
# IT NAMES A DESTRUCTIVE COMMAND, so it says what the command destroys. Anything
# saved inside the environment goes with it; anything under the Windows drives
# does not, because those are mounted rather than stored there.

[[err.prov-foreign-account]]
  The CS193V environment already has an account in it called
  {{USER}}, so setup has stopped rather than adding a second one
  called {{WANT}}.

  This normally means CS193V was set up by an earlier version of
  the course installer. The fix is to remove the environment and
  let this installer build it again:

      wsl --unregister CS193V

  This will delete everything inside the existing CS193V environment
  except for the files in your projects directory. If there is anything
  in there you need, copy it out first or ask course staff for help.
