[[help.usage]]
cs193v — the CS193V course container

  cs193v                     start the development environment
  cs193v doctor              print a report to paste when asking for help
  cs193v --stop              stop the container; only run this command if something
                             tells you to
  cs193v --reset-tunnel      resets the SSH tunnel; only run if course staff says to
  cs193v --rebuild           rebuild the course container. Your project files and
                             logins are kept
  cs193v --rebuild --logout  the same, and also log out of claude, codex, gh and vercel,
                             and forget the name and SUNetID you gave setup-git.

Your files live in the projects folder next to this script, and appear inside the
container at ~/projects. Everything else in the container is temporary.

[[err.running-as-root]]
Do not run cs193v with sudo.

Running it as root would start the container in a completely
different mode that gives up the protection the container exists
to provide, and would leave files in your projects folder that you
cannot edit afterwards.

Run it again without sudo:

    ./cs193v

If you got here because of a "permission denied" error, that error
has a different cause — please contact course staff rather than
working around it.

[[err.no-podman]]
Podman is not installed on this computer. This should not be
possible because the installation script should have installed
it. Please contact the course staff.

[[err.podman-hangs]]
Podman is installed but is not responding.

This is a known problem on Macs that have been asleep: podman
commands hang rather than failing. The usual fix is to restart
podman's virtual machine:

    podman machine stop
    podman machine start

Then try cs193v again. If that does not help, contact course
staff.

[[prompt.clock-drift]]
The container's clock is {{SKEW}} seconds away from your computer's clock.

This happens when a laptop sleeps: the small Linux virtual machine podman uses does not
always catch up on waking. It causes confusing failures that look like network
problems: secure connections rejected as "not yet valid", downloads failing,
logins refused.

The container cannot fix its own clock, so the fix is to restart podman's virtual
machine. Anything currently running in the container will stop.

[[opt.leave-clock]]
Leave it for now
[[opt.restart-machine]]
Restart the virtual machine to fix the clock (recommended)

# ═══════════════════════════════════════════════════════════════════════════════
#  WHAT `cs193v doctor` PRINTS
#
#  This report is the first thing staff ask a stuck student for, so every line of it is
#  read by somebody -- which is why it belongs here with everything else a student sees
#  rather than inline in the launcher, where it was until now.
#
#  TWO COLUMNS, AND THE LEFT ONE IS SIXTEEN CHARACTERS WIDE. doctor.row.* are the row
#  labels and everything else is a value. The report is meant to be PASTED, so its
#  alignment is load-bearing: a label wider than the gutter pushes that row's value out of
#  the column and the paste stops being readable down the page. Reword them freely, but
#  keep them short -- doctor:every-label-fits-the-gutter in 20-messages.sh is the check,
#  and it prints the width it measured when it fails.
#
#  {{HI}} AND {{OFF}} TURN THE HIGHLIGHT ON AND OFF, and they exist so that the three
#  lines which highlight one word can say the whole sentence here. The launcher fills them
#  with its yellow and its reset, or with nothing at all when NO_COLOR is set, so moving
#  the pair -- or deleting it -- is a decision this file gets to make.
#
#  NOTHING HERE IS PARSED BY ANYTHING. The state file the port rows read is tab-separated
#  and machine-written; these are the sentences drawn from it.
# ═══════════════════════════════════════════════════════════════════════════════
