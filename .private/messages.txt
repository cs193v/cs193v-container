[[help.usage]]
cs193v — the CS193V course container

  cs193v                     open a shell in the container
  cs193v doctor              print a report to paste when asking for help
  cs193v --stop              stop the container, if a terminal window was closed
                             without you noticing

  cs193v --reset-tunnel      fix it when your browser cannot reach your server
  cs193v --rebuild           start the container over. Your files and logins are kept.
                             If the course container has been updated since yours was
                             built, this builds the new one, which takes a while.
  cs193v --rebuild --logout  the same, and also log out of claude, gh and vercel, and
                             forget the name and email you gave setup-git.

Closing your terminal window stops the container, and anything running inside it. A
dev server you started will stop. Your files are safe — they live on your own computer.

Use tabs rather than a second window: CTRL+T opens one, and they all share the one
container. Only one terminal window at a time can be in the container.

Your files live in the projects folder next to this script, and appear inside the
container at ~/projects. Everything else in the container is temporary.

[[err.running-as-root]]
Do not run cs193v with sudo.

Running it as root would start the container in a completely
different mode that gives up the protection the container exists
to provide, and would leave files in your projects folder that you
cannot edit afterwards.

Run it again without sudo:

    ./cs193v

If you got here because of a "permission denied" error, that error
has a different cause — please contact course staff rather than
working around it.

[[err.no-podman]]
Podman is not installed, or it is not on your PATH.

Podman is the program that runs the course container. If you have
not installed it yet, run the course installer script. If you
believe you did install it, contact course staff and include the
output of:

    cs193v doctor

[[err.podman-hangs]]
Podman is installed but is not responding.

This is a known problem on Macs that have been asleep: podman
commands hang rather than failing. The usual fix is to restart
podman's virtual machine:

    podman machine stop
    podman machine start

Then try cs193v again. If that does not help, contact course
staff.

[[err.podman-too-old]]
Your version of podman is too old for the course container.

    you have:  {{FOUND}}
    we need:   {{NEED}} or newer

On Ubuntu or inside the WSL CS193V environment:

    sudo apt update && sudo apt install --only-upgrade podman

On a Mac: open Podman Desktop and let it update itself.

Nothing has been changed on your computer. Contact course staff if
the upgrade does not work.

[[err.podman-unreachable]]
Podman is installed but the course container cannot reach it.

On a Mac this almost always means podman's virtual machine is not
running:

    podman machine start

On Ubuntu or WSL, try:

    podman info

and send the output to course staff along with `cs193v doctor`.

[[err.rootful]]
Podman is running in "rootful" mode, and the course container
needs "rootless" mode.

This is not something to work around — rootless mode is what keeps
the container from being able to touch the rest of your computer.
Please contact course staff and include the output of:

    cs193v doctor

[[err.no-subuid]]
Your account is missing something podman needs, and we do not want
to guess at fixing it because it affects your whole computer.

Specifically: the account {{USER}} has no entry in /etc/subuid.
Podman uses that range of ID numbers to keep the container
separated from the rest of your system.

Run the course installer again — it can set this up, and it will
ask your permission before changing anything:

    bash .private/install-cs193v.sh

If that does not work, contact course staff with the output of:

    id
    cat /etc/subuid /etc/subgid

Do not hand-edit those files yourself — it usually means something
slightly unusual about how your account was created, and we would
rather see it than guess.

[[err.other-directory]]
There is already a CS193V container, and it is using a different
folder from this one.

    the container is using:  {{INUSE}}
    you ran cs193v from:     {{YOURS}}

If cs193v continued, you would be editing files in the first
folder while believing you were working in the second — so it has
stopped instead.

Two ways forward:

  * Work in the original folder:  cd {{INUSE}} && ./cs193v
  * Or start fresh in this one:   ./cs193v --rebuild

If that container is open in another terminal window right now,
run ./cs193v --stop first.

[[err.needs-a-terminal]]
cs193v could not open a shell, because it is not being run from a
terminal — its input is coming from a file or from another program
rather than from your keyboard.

If you typed ./cs193v yourself and got this, please send it to
course staff along with how you started it.

Your container is set up, and has been stopped again — it only
stays running while a terminal window is open on it. These
commands do not need a terminal, so they are the ones to use in
a script:

    cs193v --rebuild     make sure a fresh container exists
    cs193v doctor        print the status report

To run a single command inside the container:

    podman exec -it cs193v bash -lc 'your command here'

[[err.session-in-use]]
You already have a CS193V session open in another terminal window.

Switch to that window and carry on working there. Only one
window at a time can be in the container — if you want a second
place to work, open a new tab there with CTRL+T.

(You may also see this message if your previous session crashed,
or if you closed a terminal window in a way that did not shut
things down. If so, that's okay; the fix is the same.)

To stop the container so you can start again:

    cs193v --stop

[[err.build-failed]]
The course container could not be built. Podman stopped here:

{{OUT}}

This is most often a network problem. It is safe to run it again:
podman keeps every step that finished, so a second attempt picks
up at the step that failed rather than starting over.

    ./cs193v --rebuild

If it stops at the same step twice, send course staff everything
above, along with the output of:

    cs193v doctor

[[err.build-no-disk]]
The course container could not be built: this computer ran out of
disk space part-way through.

Free up some space and run it again. Podman keeps every step that
finished, so it picks up where it stopped:

    ./cs193v --rebuild

Building needs several gigabytes free — more than the finished
container ends up occupying, because the pieces are assembled
before the leftovers are cleared away.

If you cannot free up that much space, contact course staff.

[[err.create-no-disk]]
The course container was built, but there was not enough disk
space left to start it.

The build itself worked — nothing is wrong with it, and it does
not need doing again. Starting the container needs its own space
on top of the build, roughly the size of the container again.

Free up a few gigabytes and run this, which will pick up from
where it stopped:

    ./cs193v

If you cannot free up that much space, contact course staff.

[[err.no-ssh]]
The ssh command is not installed, or it is not on your PATH.

cs193v uses ssh on YOUR computer to connect your browser to the
servers you run inside the container. Without it, nothing you run
in the container could be reached at http://localhost.

The course installer sets this up along with podman, so the fix is
to run the installer script again — it will pick up from wherever
it left off and change nothing that is already correct.

If you believe you already ran it, contact course staff and include
the output of:

    cs193v doctor

[[err.tunnel-keygen]]
Could not create the keys cs193v uses to connect your browser to
the container.

This almost always means the .config folder next to this script is
not writable, or the disk is full. Check both, then try again. If
neither looks wrong, contact course staff and include the output
of:

    cs193v doctor

[[warn.tunnel-failed]]

If that does not help, send course staff the output of `cs193v doctor` and this file:

    {{LOG}}

[[warn.tunnel-ports-busy]]
These ports were already in use by another program on your computer, so servers you
run inside the container on them will NOT be reachable:

    {{PORTS}}

Use a different port from the published list, or quit whatever else is using these
and run `cs193v --reset-tunnel`. To find the culprit on a Mac or Linux machine:

    lsof -nP -iTCP:PORT -sTCP:LISTEN

[[warn.tunnel-no-ports]]
No ports are listed in your settings file, so nothing you run inside the container
will be reachable from your browser. That file should contain a CS193V_PORTS line:

    {{FILE}}

If you have not edited it, contact course staff — this line should not appear.

[[warn.tunnel-bad-port]]
Skipping "{{CHUNK}}" in the CS193V_PORTS setting: it is not a port or a port range,
so it was ignored. Everything else still works. If you did not edit that setting
yourself, contact course staff.

[[warn.tunnel-reset-not-running]]
There is no container running, so there was nothing to reconnect. The connection was
cleaned up anyway. Run ./cs193v to start the container.

[[prompt.clock-drift]]
The container's clock is {{SKEW}} seconds away from your computer's clock.

This happens when a laptop sleeps: the small Linux virtual machine podman uses does not
always catch up on waking. It causes confusing failures that look like network problems
— secure connections rejected as "not yet valid", downloads failing, logins refused.

The container cannot fix its own clock, so the fix is to restart podman's virtual
machine. Anything currently running in the container will stop.

[[opt.leave-clock]]
Leave it for now
[[opt.restart-machine]]
Restart the virtual machine to fix the clock (recommended)
