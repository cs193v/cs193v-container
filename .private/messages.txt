[[help.usage]]
The CS193V Development Environment

  cs193v                     Start the development environment
  
  cs193v doctor              Print a report to paste when asking for help
  
  cs193v --stop              Stops a container that's still running. You
                             should only need to do this if something goes
                             wrong and the container is still running after
                             you quit.

  cs193v --reset-tunnel      Resets the SSH tunnel. Use this only if directed to
                             by the course staff.
  
  cs193v --rebuild           Rebuilds the course container image. This preserves your
                             logins and project files, but wipes any other temporary files
                             and anything you installed manually.
                             
  cs193v --rebuild --logout  The same, and also log out of claude, codex, gh and vercel,
                             and forget the name and SUNetID you gave setup-git.

Your files live in the projects folder next to this script, and appear inside the
container at ~/projects. Everything else in the container is temporary.

[[err.running-as-root]]
Do not run cs193v with sudo.

Running it as root would start the container in a completely
different mode that gives up the protection the container exists
to provide, and would leave files in your projects folder that you
cannot edit afterwards.

Run it again without sudo:

    ./cs193v

If you got here because of a "permission denied" error, that error
has a different cause. Please contact course staff rather than
working around it.

[[err.no-podman]]
Podman is not installed on this computer.

Podman should have been installed when you installed the development
environment.

Run the command

    ./cs193v doctor

and contact the course staff, including the output of that command.

[[err.podman-hangs]]
Podman is installed but is not responding.

This is a known problem on Macs that have been asleep: podman
commands hang rather than failing. The usual fix is to restart
podman's virtual machine:

    podman machine stop
    podman machine start

Then try cs193v again. If that does not help, contact course
staff.

[[err.podman-too-old]]
Your version of podman is too old for the course container.

    you have:  {{FOUND}}
    we need:   {{NEED}} or newer

Inside the WSL CS193V environment, run:

    sudo apt update && sudo apt install --only-upgrade podman

On any other Linux, use your distribution's package manager to
upgrade podman -- or run the course installer again and it will
name the exact command for your system.

On a Mac: remove the podman you already have, then run the
course installer again -- it installs a version the course is
tested against. Podman Desktop's own updater may leave you on
a different one.

Nothing has been changed on your computer. Contact course
staff if that does not work, or before removing podman if you
use it for anything outside this course.

[[err.podman-unreachable]]
Podman is installed but the course container cannot reach it.

On a Mac this almost always means podman's virtual machine is not
running:

    podman machine start

On Ubuntu or WSL, try:

    podman info

and send the output to course staff along with `cs193v doctor`.

[[err.rootful]]
Podman is running in "rootful" mode, and the course container
needs "rootless" mode.

This is not something to work around. Rootless mode is what keeps
the container from being able to touch the rest of your computer.
Please contact course staff and include the output of:

    ./cs193v doctor

[[err.no-subuid]]
Your account is missing something podman needs, and we do not want
to guess at fixing it because it affects your whole computer.

Specifically: the account {{USER}} has no entry in /etc/subuid.
Podman uses that range of ID numbers to keep the container
separated from the rest of your system.

Contact course staff and include this message.

[[err.other-directory]]
There is already a CS193V container, and it is using a different
folder from this one.

    the container is using:  {{INUSE}}
    you ran cs193v from:     {{YOURS}}

If cs193v continued, you would be editing files in the first
folder while believing you were working in the second — so it has
stopped instead.

Two ways forward:

  * Work in the original folder:  cd {{INUSE}} && ./cs193v
  * Or start fresh in this one:   ./cs193v --rebuild

If that container is open in another terminal window right now,
run ./cs193v --stop first.

[[err.needs-a-terminal]]
cs193v could not open a shell, because it is not being run from a
terminal. Its input is coming from a file or from another program
rather than from your keyboard.

If you typed ./cs193v yourself and got this, please contact
the course staff.

[[err.session-in-use]]
You already have a CS193V session open in another terminal window.

Switch to that window and carry on working there. Only one
window at a time can be in the container. If you want a second
place to work, open a new tab there with CTRL+T.

(You may also see this message if your previous session crashed,
or if you closed a terminal window in a way that did not shut
things down. If so, that's okay; the fix is the same.)

To stop the container so you can start again:

    ./cs193v --stop

[[err.build-no-disk]]
The course container could not be built: this computer ran out of
disk space part-way through.

Free up some space and run it again. Podman keeps every step that
finished, so it picks up where it stopped:

    ./cs193v --rebuild

Building needs several gigabytes free — more than the finished
container ends up occupying, because the pieces are assembled
before the leftovers are cleared away.

If you cannot free up that much space, contact course staff.

[[err.create-no-disk]]
The course container was built, but there was not enough disk
space left to start it.

The build itself worked — nothing is wrong with it, and it does
not need doing again. Starting the container needs its own space
on top of the build, roughly the size of the container again.

Free up a few gigabytes and run this, which will pick up from
where it stopped:

    ./cs193v

If you cannot free up that much space, contact course staff.

[[prompt.clock-drift]]
The container's clock is {{SKEW}} seconds away from your computer's clock.

This happens when a laptop sleeps: the small Linux virtual machine podman uses does not
always catch up on waking. It causes confusing failures that look like network problems
— secure connections rejected as "not yet valid", downloads failing, logins refused.

The container cannot fix its own clock, so the fix is to restart podman's virtual
machine. Anything currently running in the container will stop.

[[opt.leave-clock]]
Leave it for now
[[opt.restart-machine]]
Restart the virtual machine to fix the clock (recommended)
