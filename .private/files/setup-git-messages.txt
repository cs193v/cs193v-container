#  Edit freely — wording and tone here are yours, and nothing in the script depends on the
#  phrasing. Same format as .private/messages.txt and read by the same msg(): each block
#  starts with [[key]] on its own line and runs to the next [[key]], and {{PLACEHOLDER}} is
#  substituted at runtime. 20-messages.sh cross-references this file against setup-git, so an
#  orphan key, a missing one, or a {{PLACEHOLDER}} nobody supplies is caught automatically.
#
#  WHY THIS IS NOT messages.txt. setup-git runs INSIDE the container, and the container cannot
#  see messages.txt — only projects/ is bind-mounted. So this file is installed into the image
#  at /etc/cs193v/setup-git-messages.txt, which also means cs193v.buildhash covers it: reword
#  something here and students are prompted to rebuild, so they actually get the new words.
#
#  HARD-WRAP AT 76 COLUMNS, AND THAT NUMBER IS LOAD-BEARING (issue #58). render() indents every
#  line by two, so 76 is the widest line that does not SOFT-wrap on an 80-column terminal — and
#  a soft-wrapped line costs a second row. This file was wrapped at 94 before, which is why the
#  token screen ran to 53 rows on 80 columns when only 23 of them are visible: the container's
#  tmux takes one row for its status line. The rule is asserted by
#  20-messages.sh :: sgkeys:every-line-fits-78-columns; the one exemption is the line carrying
#  {{URL}}, which is 157 characters of GitHub's making and is issue #67's to shorten.
#
#  *ASTERISKS MARK EMPHASIS* and are rendered as bright cyan, the same colour the arrow-key
#  menu highlights with. They come in pairs on one line. Nothing that ends up inside a box may
#  use them: box() measures display columns and the markup is removed after it counts, so the
#  box would come out two columns narrow. 20-messages.sh asserts that.
#
#  House style, worth keeping: say what happened, say what to do, and never make a student
#  guess whether something is their mistake or ours.

[[err.clone]]
*Oh no, we can't reach your practice repository!*

    {{SANDBOX}}

Your access token was accepted by GitHub, so this is either the wrong

1. *Your SUNetID.* That repository is named after it. If it is not yours,
   run *setup-git* again and choose *Start over*.

   https://github.com/orgs/{{ORG}}/invitation

[[err.clone-wrong-owner]]
*Oh no, your access token belongs to the wrong account!*

The token you pasted was created with *@{{LOGIN}}* as its *Resource owner*,
which means it can only reach your own repositories — not the course's. It
needs to be *{{ORG}}* instead.

Resource owner cannot be changed after a token has been created, so this
one cannot be fixed and you will need to make a new one. When you do, the
*Resource owner* box is the second thing on the page, above
*Repository access*:

    https://github.com/settings/personal-access-tokens

You can delete the old token from that same page once the new one works.

[[err.push]]
*Oh no, we can't* git push*!*

This is most likely because your access token's *Contents* permission is set
to *Read-only* instead of *Read and write*. To correct this:

  1. Open https://github.com/settings/personal-access-tokens
  2. Click your *CS193V* token.
  3. Scroll to *Permissions* and set *Contents* to *Read and write*.
  4. Scroll to the bottom and click *Update token*.

You do not need to make a new token, and your token will not change — you
can keep using the one you already pasted.

[[err.issues]]
*Oh no, we can't work with GitHub issues!*

This is most likely because your access token's *Issues* permission is not
set to *Read and write*. To correct this:

  1. Open https://github.com/settings/personal-access-tokens
  2. Click your *CS193V* token.
  3. Scroll to *Permissions* and set *Issues* to *Read and write*.
  4. Scroll to the bottom and click *Update token*.

You do not need to make a new token, and your token will not change — you
can keep using the one you already pasted.

[[err.prs]]
*Oh no, we can't work with pull requests!*

This is most likely because your access token's *Pull requests* permission
is not set to *Read and write*. To correct this:

  1. Open https://github.com/settings/personal-access-tokens
  2. Click your *CS193V* token.
  3. Scroll to *Permissions* and set *Pull requests* to *Read and write*.
  4. Scroll to the bottom and click *Update token*.

You do not need to make a new token, and your token will not change — you
can keep using the one you already pasted.

[[err.network]]
*Oh no, we can't reach GitHub!*

This usually means the network isn't working, rather than anything being
wrong with your setup. Check that you can load https://github.com in your
browser, then run *setup-git* again.

[[err.rate-limit]]
*GitHub has asked us to slow down.*

This happens when a lot of people set things up at the same time. Wait a
minute, then run *setup-git* again.
